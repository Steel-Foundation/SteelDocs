当你在终端中运行 SteelMC 时，控制台同时也是一个功能完备的交互式命令行。日志输出会在底部的输入行上方滚动，你在输入行中键入的命令将以控制台发送者（Console Sender）身份执行，并自动绕过所有玩家权限检查。

## 关闭服务器

| 快捷键   | 行为说明                                       |
| -------- | ---------------------------------------------- |
| `Ctrl+C` | 当输入行为空时，触发优雅停服                   |
| `Ctrl+Q` | 无论输入行中是否有内容，立即触发优雅停服       |

按下 `Ctrl+C` 时会按以下顺序依次判断：

1. 如果当前有选中的文本，则复制选中文本。
2. 如果输入行中有尚未执行的文字，则清空当前输入行。
3. 如果输入行已经为空，则开始优雅关闭服务器。

因此，如果你在输入命令到一半时想要关服，可以连续按两次 `Ctrl+C`，或者直接按一次 `Ctrl+Q`。

执行 `stop` 命令同样会关闭服务器。所有关服途径都会走同一套优雅停服流程：在进程退出前完整保存所有世界存档与玩家数据，并将控制台命令历史记录写入磁盘。

### 操作系统信号处理

当操作系统请求进程停止时（例如作为 systemd 服务运行、在 Docker 容器中停止或无交互式终端时），SteelMC 同样会执行优雅停服：

| 平台    | 捕获处理的信号 / 事件                                       |
| ------- | ----------------------------------------------------------- |
| Unix    | `SIGINT`、`SIGTERM`、`SIGHUP`                               |
| Windows | `Ctrl+C`、`Ctrl+Break`、关闭控制台窗口、用户注销、系统关机  |

只有第一个停止信号会启动关服保存流程；在存档保存完成之前，后续重复发送的信号会被忽略，因此多按一次 `Ctrl+C` 不会中断正在进行的存档写入。

:::caution
`SIGKILL`（`kill -9`）或通过任务管理器强制结束进程无法被程序捕获处理，尚未落盘的数据将会丢失。
:::

## 编辑输入行

| 快捷键                 | 行为说明                                           |
| ---------------------- | -------------------------------------------------- |
| `Enter`                | 执行当前输入的命令                                 |
| `Left` / `Right`       | 左右移动光标                                       |
| `Home` / `End`         | 跳转到行首或行尾                                   |
| `Backspace` / `Delete` | 删除光标前或光标后的字符                           |
| `Insert`               | 切换覆盖输入模式（激活时光标变为实心方块）         |
| `Esc`                  | 清空当前输入行                                     |

## 文本选择与复制

| 快捷键                       | 行为说明                               |
| ---------------------------- | -------------------------------------- |
| `Shift+Left` / `Shift+Right` | 向左或向右逐字符扩展/收缩选区          |
| `Shift+Home`                 | 从当前光标位置选中到行首               |
| `Shift+End`                  | 从当前光标位置选中到行尾               |
| `Ctrl+A`                     | 全选整行输入                           |
| `Ctrl+C`                     | 复制当前选区内容                       |
| `Ctrl+X`                     | 剪切当前选区内容                       |

在存在活动选区时直接输入字符、按 `Backspace` 或 `Delete` 会替换或删除选中的文本；按 `Left` 或 `Right` 则会取消选中并将光标移至选区起点或终点。

复制功能基于终端的 OSC 52 转义序列实现，因此需要终端本身支持 OSC 52（例如 kitty、WezTerm、Alacritty、iTerm2、Windows Terminal 等）。部分终端或终端复用器（如 `tmux`）可能需要手动开启 OSC 52 剪贴板访问权限。粘贴文本请直接使用终端自身的粘贴快捷键。

:::note
`Ctrl+C` 仅在有文本被选中时执行复制；若未选中文本，则会清空输入行（输入行已空时则触发关服）。
:::

## 命令历史记录

| 快捷键            | 行为说明         |
| ----------------- | ---------------- |
| `Up` / `Ctrl+P`   | 上一条历史命令   |
| `Down` / `Ctrl+N` | 下一条历史命令   |
| `Ctrl+R`          | 反向搜索历史命令 |

命令历史记录保存在[日志目录](../../configuration/server-configuration)（`log.log_path`，默认为 `./.logs`）下的 `history.txt` 文件中，跨重启持久保留。控制台最多保留最近 `log.max_history` 条命令（默认为 `50` 条）。

### 反向搜索历史命令（Reverse Search）

按下 `Ctrl+R` 可像在 Bash 中一样向后搜索命令历史。此时提示符会变为搜索状态：

```text
(reverse-i-search)`give': give @s diamond 64
```

随着你输入关键词，输入行会实时展示包含该关键词的最新一条历史命令，并高亮显示匹配部分。如果没有匹配结果，提示符会显示 `failed reverse-i-search`，并在屏幕上保留上一次匹配的命令。

| 快捷键                      | 行为说明                                         |
| --------------------------- | ------------------------------------------------ |
| `Ctrl+R`                    | 跳转到上一条更早的匹配命令                       |
| `Backspace`                 | 删除搜索关键词的最后一个字符                     |
| `Enter`                     | 直接执行当前匹配到的命令                         |
| `Tab`                       | 将匹配的命令保留在输入行中以便继续编辑           |
| `Esc` / `Ctrl+C` / `Ctrl+G` | 取消搜索并恢复搜索前输入行中原有的内容           |

按下方向键或 `Home` 等其他导航键同样会将当前匹配的命令保留在输入行中，并立即执行对应的光标移动操作。选中某条历史命令后，按 `Up` 和 `Down` 会从该条命令所在的历史位置继续向上或向下翻阅。

## 命令自动补全（Tab Completion）

按下 `Tab` 键可呼出当前命令的自动补全建议列表。当补全列表打开时：

| 快捷键            | 行为说明                               |
| ----------------- | -------------------------------------- |
| `Up` / `Ctrl+P`   | 向上高亮选择上一条补全建议             |
| `Down` / `Ctrl+N` | 向下高亮选择下一条补全建议             |
| `Tab`             | 插入当前高亮的补全内容并关闭建议列表   |

补全列表会随着你继续输入字符或移动光标而实时更新。
