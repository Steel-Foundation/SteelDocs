喺本指南入面，你將會了解到開始為 SteelMC 貢獻程式碼所需掌握嘅全部必要知識與流程規範。

:::note
本指南假設你已經掌握咗 Git 同 GitHub 嘅基本操作與協作流程。
:::

:::tip
身為新貢獻者，請盡量將同時開啟嘅 Pull Request（PR）數量控制喺 3 個以內，以便維護者團隊喺開啟新 PR 之前先對現有 PR 提供即時嘅程式碼審查回饋。
此外，建議先由較小、較簡單嘅貢獻開始（單次修改量大約喺 1,000 行以內），咁樣審查同合併嘅速度會快好多。

維護者通常係喺空餘時間審查 PR，因此初次審查可能需要幾日時間。如果一個禮拜之後仲未收到回覆，歡迎喺 Discord 入面交流或者喺你嘅 PR 下面留言提醒我哋。
:::

## 開始之前

喺正式郁手寫 Code 之前，你需要先了解 Steel 設計哲學中嘅幾項核心理念。

### 程式碼哲學

為 Steel 編寫程式碼時請記住：我哋需要嘅係 **完整且成熟嘅解決方案，而唔係半製成品嘅權宜之計**。對於中大型系統，必須先深入研究該機制喺原版 Minecraft 入面嘅運作方式，並思考點樣將佢設計得更合理、更高效。我哋喺建構時始終注重打好穩固嘅工程基礎，呢個意味住所有程式碼必須具備高可讀性、詳盡嘅程式碼文檔（Doc Comments）、良好嘅凝聚性，並達到正式環境等級標準。如果你負責嘅系統喺未來可能需要支援模組擴展，請由一開始就為未來嘅擴展性預留空間。

### AI 輔助政策

我哋唔限制你使用 AI 工具嘅方式，前提係你必須確保自己**完全理解 PR 入面嘅每一行程式碼**，能夠清楚解釋開發過程入面嘅所有架構決策，並能說明喺提交 PR 之前你評估過邊啲替代方案、點解冇採用佢哋。

### 程式碼規範

喺開始之前，請務必閱讀[我哋嘅程式碼規範](../code-standard)。

## 開發準備

了解咗我哋嘅設計哲學之後，就可以開始著手開發喇，不過喺呢個之前……

### 選擇要做啲咩

搵切入點嘅方法有好多，我哋推薦按以下步驟進行：

- 查看[已開啟嘅 PR](https://github.com/Steel-Foundation/SteelMC/pulls)，了解其他人正在開發邊啲內容，避免重複投入
- 查看[未解決嘅 Issue](https://github.com/Steel-Foundation/SteelMC/issues)，挑選可修復嘅問題（推薦按 `good first issue` 標籤進行篩選）
- 查看[實現進度追蹤器](../../tracker)，查看邊啲方塊、物品、實體或指令尚未實現
- 喺[我哋嘅 Discord 社群](/discord)嘅 `#dev-work` 頻道入面交流確認，確認你計劃實現嘅功能係咪適合目前階段

### 建立新分支

首先，如果你嘅 GitHub 帳號下面仲未有 SteelMC 嘅 Fork 副本，請前往 [Fork 頁面建立](https://github.com/Steel-Foundation/SteelMC/fork)。

喺你嘅 Fork 倉庫入面，建立一個新分支，並喺分支名稱中明確體現你正在實現嘅功能。

:::caution
除非你非常清楚自己在做緊咩，否則請務必基於我哋嘅 `main` 或 `dev` 主幹分支建立新分支，切勿基於某個正在開發中嘅功能分支切出。
:::

將該分支 Clone 到本機開發設備即可開始編寫程式碼。

## 開發完成後嘅檢查

當你完成功能實現、通過充分嘅自我測試、確保本地分支已同步至最新提交並推送至 GitHub 遠端分支後，就可以向官方倉庫發起 Pull Request 喇。但喺提交前，請先確保你嘅程式碼已通過各項質量檢查。

:::note
程式碼庫入面設定咗自動化質量檢查，可運行以下指令檢查程式碼規範：

```bash
# 運行靜態程式碼檢查（Clippy）
cargo clippy -r --all-targets --all-features

# 檢查程式碼格式是否符合規範
cargo fmt --all --check

# 檢查程式碼入面嘅錯別字
typos
```

關於點樣安裝 `typos` 工具，請參考[呢度嘅安裝說明](https://crates.io/crates/typos-cli#install)。

程式碼庫入面內建咗 [Prek](https://prek.j178.dev/) 設定檔，你可以直接喺本地運行 `prek` 自動執行完整嘅審查前檢查：

```bash
prek run
```
:::

提交 PR 時，請按官方範本清楚填寫 PR 標題與說明描述。

此外，你可以喺 GitHub 上直接請求維護者審查，或將 PR 連結發送到 Discord 嘅 `prs-ready-for-review` 頻道，方便維護者即時跟進。

維護者可能會向你提出修改請求（Request Changes）。如果遇到呢種情況，請根據意見修改程式碼，或者說明你認為目前做法更好嘅理由。

最終，你嘅程式碼將會被合併入主幹分支。當嗰一刻來臨，請記住：\**「多謝並祝賀你為 SteelMC 貢獻嘅程式碼！」**
