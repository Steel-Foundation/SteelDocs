## اختيار طريقة التثبيت المناسبة

اختر الطريقة التي تتناسب مع بيئة التشغيل التي ستعمل عليها:

- إذا كنت ترغب في تشغيل Steel مباشرة على نظام التشغيل لديك، فاستخدم الملفات التنفيذية الجاهزة.
- إذا كنت تستخدم Kubernetes أو Docker Swarm أو بيئة Docker قياسية، فإن حاوية Docker هي الخيار الموصى به.
- إذا كنت تستخدم لوحة تحكم مثل Pelican أو Pterodactyl، فاستخدم قالب Egg المخصص لـ Steel بصيغة JSON أو YAML.
- إذا كنت ترغب في الحصول على أقصى سرعة ممكنة لمعالجك أو إذا كانت منصتك غير مدعومة بالملفات الجاهزة، فقم ببناء Steel من المصدر مباشرة لنظامك.

| الطريقة | Linux x64 | Linux arm64 | Linux armv7 | Linux armv6 | Windows x64 | Windows arm | Mac arm | Mac x64 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| [ملف تنفيذي](#الملفات-التنفيذية-الجاهزة) | ✅ | ❌ | ❌ | ❌ | ✅ | ❌ | ✅ | ❌ |

## الملفات التنفيذية الجاهزة

تتوفر الملفات التنفيذية الجاهزة في [صفحة التنزيل](../../download) للمنصات التالية:

- Linux (x86_64)
- Windows (x86_64)
- MacOS (ARM)

كما يمكنك العثور على نفس الملفات عبر صفحة [إصدارات GitHub](https://github.com/Steel-Foundation/SteelMC/releases).

بعد اكتمال التنزيل، افتح موجه الأوامر المفضل لديك (مثل PowerShell أو Terminal أو Kitty وغيرها) في مجلد الملف التنفيذي، ثم نفذ الأمر التالي:

```bash
# Windows
./steel.exe

# MacOS / Linux
./steel
```

:::caution
لمستخدمي MacOS، يلزم تفعيل وضع المطورين (Development Mode) لتشغيل Steel نظراً لعدم توقيعه رسمياً بشهادة مطور معتمدة.

يمكنك تفعيل ذلك بتشغيل الأمر التالي في Terminal وإدخال كلمة مرور المسؤول:

```bash
sudo devtools enable
```
:::

## Docker

لا يوفر مشروع Steel وسماً باسم `latest` لصور Docker. استخدم وسماً يحدد الإصدار بدقة بدلاً من ذلك، لضمان الترقية المخططة وتجنب تحديث الحاوية بشكل غير متوقع.

يتوفر الوسم `nightly` لاختبار الإضافات والتجربة المبكرة للتغييرات القادمة. يتتبع هذا الوسم أحدث التغييرات على فرع `master` وقد يحتوي على أخطاء برمجية لم تُعالج بعد. لا تستخدم `nightly` في بيئة الإنتاج الفعلية.

### تشغيل الصورة

شغّل حاوية Steel مع تمرير منفذ الخادم وتعيين المجلدات المحلية للإعدادات وحفظ العوالم:

```bash
docker run -d -it -p 25565:25565 -v ./config:/config -v ./saves:/saves -v ./logs:/logs --name steel-mc ghcr.io/steel-foundation/steelmc:<version>
```

:::tip
للوصول إلى وحدة تحكم (Console) خادم Steel داخل حاوية Docker:
```bash
docker attach <steel-mc|container name>
```
:::

:::note
أمر تنزيل نسخة nightly لـ Docker هو: `docker pull ghcr.io/steel-foundation/steelmc:nightly`
:::

:::tip
يمكن إعداد نفس التكوين عبر Docker Compose (الخيار الموصى به):

```yaml
# docker-compose.yml
services:
  steel:
    image: ghcr.io/steel-foundation/steelmc:<version>
    stdin_open: true
    tty: true
    container_name: steel-mc
    ports:
      - 25565:25565
    volumes:
      - ./config:/config
      - ./saves:/saves
      - ./logs:/logs
```

يوفر Docker Compose وسيلة منظمة لحفظ معاملات `docker run` داخل ملف واحد.\
يمكنك الاطلاع على الدليل الكامل لـ Docker Compose هنا: https://docs.docker.com/reference/compose-file/
:::

### كيفية تعديل المنافذ والمجلدات

إذا لم تكن على دراية بكيفية ضبط إعدادات Docker، فإليك دليلاً سريعاً لأهم المعاملات:

- **`-p` (`--port`, `ports`):** يمثل الرقم الأول منفذ الجهاز المضيف (Host port) الذي يمكن تغييره. بينما يمثل الرقم الثاني المنفذ داخل حاوية Docker ويجب ألا يتغير إلا إذا تم تعديله في إعدادات Steel. على سبيل المثال، `-p 1111:25565` يجعل خادم ماين كرافت متاحاً عبر المنفذ `1111` على خادمك.
- **`-v` (`--volume`, `volumes`):** المسار قبل النقطتين الرأسيتين هو المسار على جهازك المضيف، ويمكن أن يكون نسبياً بالنسبة لملف compose. المسار بعد النقطتين هو المسار داخل حاوية Docker ولا ينبغي تغييره.

## البناء الذاتي من المصدر

### المتطلبات الأساسية

- **حزمة أدوات Rust nightly** - يستخدم Steel ميزات من إصدار Rust 2024
- **نظام تشغيل 64-بت** - Linux أو MacOS أو Windows
- **Git** - لاستنساخ المستودع

### تثبيت Rust

إذا لم تكن قد قمت بتثبيت Rust بعد، فاستخدم أداة [rustup](https://rustup.rs/):

```bash
# لأنظمة Unix فقط (مثل MacOS و Linux)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

يتطلب Steel استخدام حزمة nightly. يحتوي المستودع على ملف `rust-toolchain.toml` الذي يحدد الإصدار الصحيح تلقائياً.

### البناء والترجمة من المصدر

```bash
# استنساخ المستودع
git clone https://github.com/Steel-Foundation/SteelMC.git
cd SteelMC

# البناء في وضع الإنتاج (موصى به للتشغيل)
cargo build-native --release
```

:::note
**سيكون الملف التنفيذي الناتج في المسار `./target/release/steel`**
:::

:::caution
إذا كنت ترغب في البناء لمنصات armv6 و armv7، فستحتاج أيضاً إلى استنساخ مستودع simdnbt وتعديل مساره في `Cargo.toml` لاستخدام نسختك المحلية وإزالة قيود 64-bit من مكتبة simdnbt.
للحصول على المساعدة، تواصل معنا عبر [ديسكورد](/discord).
:::

#### أوامر البناء

| الأمر | الغرض |
| :--- | :--- |
| `cargo build-native` | بناء لوضع التنقيح (Debug) (ترجمة أسرع، تشغيل أبطأ) (مع تحسينات معمارية المعالج) |
| `cargo build-native --release` | بناء لوضع الإنتاج (ترجمة أبطأ، أداء عالي وأمثل) (مع تحسينات معمارية المعالج) |
| `cargo build` | بناء لوضع التنقيح (ترجمة أسرع، تشغيل أبطأ) |
| `cargo build --release` | بناء لوضع الإنتاج (ترجمة أبطأ، أداء عالي) |
| `cargo check` | فحص سريع لصحة القواعد والأنواع البرمجية |
| `cargo test` | تشغيل حزمة الاختبارات الآلية |
| `cargo clippy` | تشغيل أداة التحليل الثابت (Linter) |

:::caution
لا يمكن تشغيل البناء الأصلي (Native builds) على أجهزة أخرى ذات معمارية مختلفة؛ بل يعمل فقط على نفس الجهاز أو جهاز بنفس معمارية المعالج تماماً.
:::

#### ميزات البناء الاختيارية (Build Features)

يدعم Steel ميزات بناء اختيارية يمكن تفعيلها باستخدام `--features`:

```bash
# تفعيل اكتشاف قفل المزامنة المتبادل Deadlock (لوضع التنقيح فقط)
cargo build-native --features deadlock_detection

# تفعيل تحليل الذاكرة (Heap profiling) عبر dhat
cargo build-native --features dhat-heap

# تعطيل مخصص الذاكرة الافتراضي mimalloc
cargo build-native --no-default-features
```

**الميزات المتاحة:**

| الميزة | الوصف |
| :--- | :--- |
| `mimalloc` | استخدام مخصص الذاكرة mimalloc (مفعل افتراضياً) |
| `deadlock_detection` | تفعيل كشف حالات التعليق والـ Deadlock عبر parking_lot |
| `dhat-heap` | تفعيل أداة تحليل الذاكرة باستخدام dhat |

تعد ميزة **Deadlock Detection** مفيدة أثناء التطوير إذا كنت تواجه حالات تجمد أو تشك في مشاكل تتعلق بأقفال المزامنة.

### تشغيل الخادم

```bash
# التشغيل المباشر عبر cargo (وضع التنقيح)
cargo run-native

# التشغيل مع تحسينات الإنتاج
cargo run-native --release

# أو تشغيل الملف التنفيذي المترجم مباشرة
./target/release/steel
```
